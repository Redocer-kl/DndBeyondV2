# AI Character Generation Service  
**FastAPI + Celery + Ollama**

Микросервис для автоматической генерации персонажей D&D 5e по текстовому описанию (концепту) пользователя с использованием локальной LLM (Ollama) и асинхронной очереди задач.

---

## Архитектура взаимодействия с основным бэкендом (Go)

Микросервис является изолированным вычислительным узлом и **не имеет прямого доступа к базе данных PostgreSQL**.

1. **Бэкенд на Go** принимает запрос от фронтенда с концептом персонажа.
2. Go сохраняет лог запроса в свою БД и отправляет HTTP `POST` запрос на эндпоинт FastAPI `/api/v1/generate`.
3. FastAPI мгновенно возвращает `task_id` (UUID задачи Celery). Go сохраняет этот ID у себя.
4. Celery-воркер в фоновом режиме запрашивает генерацию у Ollama, а затем через Pydantic-схемы автоматически рассчитывает:
   - распределение **Standard Array** по приоритетам от ИИ;
   - расовые бонусы к характеристикам, скорость и размер;
   - модификаторы параметров, класс доспеха (**AC**) и хиты (**HP**) для 1-го уровня;
   - спасброски класса.
5. **Фронтенд или Go-бэкенд** опрашивают эндпоинт `/api/v1/status/{task_id}` (Long Polling). Как только статус становится `success`, сервис возвращает **полностью готовый и рассчитанный JSON персонажа**, который Go может без дополнительной валидации записать в PostgreSQL.

## Быстрый запуск для разработки

### 1. Подготовка окружения

Убедитесь, что у вас запущены:

- **Redis** (порт `6379`)
- **Ollama** с нужной моделью, например `gemma2:9b`

### 2. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 3. Запуск Celery-воркера

```bash
celery -A app.tasks.celery_app worker --loglevel=info
```

### 4. Запуск FastAPI-сервера

```bash
uvicorn app.main:app --host 127.0.0.1 --port 8001 --reload
```

Swagger-документация будет доступна по адресу:

```text
http://127.0.0.1:8001/docs
```

---

## Запуск через Docker

### 1. Сборка образа

```bash
docker build -t ai-generation-service .
```

### 2. Запуск контейнера в режиме API (FastAPI)

```bash
docker run -d \
  --name ai-api \
  -p 8001:8001 \
  -e REDIS_URL=redis://<твой_ip_или_контейнер>:6379/0 \
  -e OLLAMA_HOST=http://<твой_ip_хоста>:11434 \
  ai-generation-service
```

### 3. Запуск контейнера в режиме воркера (Celery)

```bash
docker run -d \
  --name ai-worker \
  -e REDIS_URL=redis://<твой_ip_или_контейнер>:6379/0 \
  -e OLLAMA_HOST=http://<твой_ip_хоста>:11434 \
  ai-generation-service \
  celery -A app.tasks.celery_app worker --loglevel=info
```

## Спецификация API

### 1. Запустить генерацию

**URL:** `/api/v1/generate`  
**Method:** `POST`

#### Payload

```json
{
  "concept": "Скрытный плут хафлинг, который вырос на улицах большого города."
}
```

#### Response `202 Accepted`

```json
{
  "task_id": "8fa7dfbd-b65a-4ba4-9721-aef4f0eb4871",
  "status": "pending",
  "message": "Генерация персонажа успешно запущена."
}
```

---

### 2. Проверить статус задачи

**URL:** `/api/v1/status/{task_id}`  
**Method:** `GET`

#### Response в процессе

```json
{
  "status": "pending"
}
```

#### Response при успехе

Возвращает объект со статусом `success` и полным телом готового персонажа.

---

## Примечания

- Сервис рассчитан на асинхронную генерацию.
- Основная логика расчётов вынесена в Pydantic-схемы.
- Результат генерации можно сохранять в PostgreSQL на стороне Go-бэкенда без дополнительной валидации.
